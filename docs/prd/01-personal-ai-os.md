# Personal AI OS 产品需求文档

> 版本：v0.1
> 状态：初稿，等待个性化修改
> 产品形态：桌面优先的响应式 Web App
> 核心关键词：个人信息中枢、AI Agent、知识库、目标管理、可解释执行

## 1. 产品概述

Personal AI OS 是一个集成日程、笔记、任务、目标和个人知识库的智能工作台。它不只是把多个工具放进同一界面，而是让 AI 在获得用户授权的前提下理解这些信息之间的关系，帮助用户完成“记录—整理—计划—行动—复盘”的闭环。

一句话定位：**让分散的个人信息变成一个可询问、可规划、可执行的智能系统。**

## 2. 背景与问题

目标用户通常同时使用日历、待办、笔记、网盘和聊天工具，信息被分散在多个入口中，产生四类问题：

- 记录容易，回顾困难；用户知道自己记过，却找不到具体位置。
- 日程、任务和长期目标割裂，每天很忙但无法判断是否接近目标。
- 传统搜索依赖准确关键词，无法回答跨多条记录的问题。
- AI 助手经常只给建议，无法基于用户真实数据采取受控行动。

## 3. 产品目标与非目标

### 3.1 产品目标

- 用一个统一入口管理个人日程、笔记、任务、目标和知识资料。
- 让用户通过自然语言检索自己的数据，并获得带来源引用的答案。
- 将目标拆解为可执行计划，并关联到任务和日历。
- 让 AI 在用户确认后创建、修改或整理内容，所有操作可追踪、可撤销。
- 通过每日聚焦和每周复盘，让系统持续产生实际价值。

### 3.2 首版非目标

- 不替代完整的企业项目管理、团队协作或 CRM 产品。
- 不承诺自动处理用户全部生活决策。
- 不在 MVP 中集成所有第三方笔记和日历平台。
- 不允许 AI 在没有确认的情况下发送消息、删除内容或修改外部系统。
- 不提供医疗、法律、投资等高风险专业决策。

## 4. 目标用户

### 4.1 核心用户：多线程学习与工作的个人

- 典型身份：大学生、开发者、设计师、自由职业者、知识工作者。
- 特征：同时推进多个目标，经常记录资料，希望减少工具切换。
- 核心诉求：今天应该做什么、某项资料在哪里、当前目标进展如何。

### 4.2 次要用户：个人知识管理爱好者

- 已使用 Notion、Obsidian、日历或待办工具。
- 更重视信息连接、标签、双向链接、导入导出和数据所有权。

## 5. 核心使用场景

1. 用户随手输入“下周三交数据库作业”，系统识别时间与任务，等待确认后创建任务。
2. 用户询问“我最近关于毕业设计记录了哪些想法”，系统检索笔记并引用原文来源。
3. 用户创建“三个月完成 AI 项目”的目标，AI 建议里程碑和每周投入，用户确认后生成任务。
4. 每天早晨，系统结合日历、任务优先级和目标进度生成“今日聚焦”。
5. 每周末，系统总结完成情况、延期原因和下周风险，用户可以编辑后保存为周报。

## 6. 体验原则

- **先可信，再聪明**：任何结论都能追溯到用户数据或明确标记为建议。
- **先预览，再执行**：影响用户数据的 AI 操作先展示变更预览。
- **少而聚焦**：首页只回答“发生了什么、今天做什么、目标是否偏离”。
- **数据属于用户**：支持导出和删除，连接第三方服务时采用最小权限。
- **渐进式复杂度**：新用户可从任务和笔记开始，不必先配置复杂系统。

## 7. 信息架构

| 一级模块 | 主要内容 |
| --- | --- |
| Today | 今日聚焦、日程、关键任务、收件箱、风险提醒 |
| Inbox | 快速记录、AI 识别、待整理内容 |
| Calendar | 日/周/月视图、日程与任务时间块 |
| Goals | 目标、里程碑、关键结果、进度与风险 |
| Knowledge | 笔记、资料、标签、关联和语义搜索 |
| Assistant | 对话、数据引用、操作预览和执行历史 |
| Review | 每日记录、周复盘、趋势与改进建议 |
| Settings | 账号、AI、数据连接、通知、隐私与导出 |

## 8. 核心用户流程

### 8.1 快速记录到可执行事项

1. 用户在全局输入框输入文字或粘贴链接。
2. 系统判断内容类型：笔记、任务、日程、资料或暂不确定。
3. 系统展示解析结果与可编辑字段。
4. 用户确认保存；不确定内容进入 Inbox。
5. 保存成功后展示其与目标、日期或其他笔记的关联建议。

### 8.2 基于知识库提问

1. 用户向 Assistant 提问。
2. 系统检索有权限访问的相关内容。
3. AI 生成回答，并在段落旁展示引用来源。
4. 用户可以打开原文、纠正答案或将结果保存为笔记/任务。
5. 没有足够证据时，系统明确说明“不足以回答”。

### 8.3 从目标生成计划

1. 用户填写目标、截止时间、动机和每周可投入时间。
2. AI 生成里程碑、任务建议、依赖关系和风险。
3. 用户逐项编辑、接受或删除建议。
4. 系统创建目标结构，并建议将近期任务放入日历。
5. 后续根据完成情况提示偏差，但不自动重排已确认日程。

## 10. AI 能力设计

### 10.1 AI 可用工具

- `search_knowledge`：检索笔记和资料，只读。
- `list_schedule`：读取指定时间范围内的任务与日程，只读。
- `create_task_draft`：生成任务草稿，不直接落库。
- `create_event_draft`：生成日程草稿，不直接落库。
- `update_item_draft`：生成修改预览，不直接落库。
- `summarize_review`：基于指定时间范围生成复盘草稿。

### 10.2 回答约束

- 回答中的个人事实必须来自当前用户有权限的数据。
- 引用至少包含来源标题、内容类型、更新时间和可定位片段。
- 建议与事实在视觉上明确区分。
- AI 不确定时应提出澄清问题，不编造缺失日期、完成状态或用户偏好。
- 不把用户私人内容用于公开训练或跨用户检索。

## 11. 核心数据模型

| 实体 | 关键字段 | 关系 |
| --- | --- | --- |
| User | id、email、timezone、preferences | 拥有一个或多个工作区 |
| Workspace | id、ownerId、name | 聚合所有个人数据 |
| InboxItem | rawContent、predictedType、status | 可转化为其他实体 |
| Task | title、status、priority、dueAt、estimate | 可关联目标、时间块和笔记 |
| CalendarEvent | title、startAt、endAt、source | 可关联任务或外部日历 |
| Goal | title、deadline、status、progressRule | 包含里程碑和任务 |
| Milestone | title、dueAt、weight、status | 属于一个目标 |
| Note | title、content、tags、embeddingStatus | 可关联目标、任务和其他笔记 |
| Resource | url、title、snapshot、sourceTime | 作为知识检索来源 |
| Conversation | title、createdAt、model | 包含多条消息与引用 |
| ToolExecution | tool、input、preview、result、status | 用于审计与撤销 |
| Review | period、content、metricsSnapshot | 保存周复盘结果 |

## 12. 权限、隐私与安全

- 用户数据必须按 `userId/workspaceId` 隔离，服务端每次查询均校验权限。
- 第三方令牌加密保存，日志中不得输出令牌、完整笔记或对话正文。
- 检索索引删除应与原始内容删除同步，避免“正文删了但 AI 仍能搜到”。
- 对外部日历的读取和写入权限分开申请；MVP 默认只读。
- 高风险操作、批量修改和删除必须二次确认，并保留审计记录。
- 演示模式使用独立数据集，定时恢复，不允许上传敏感个人资料。

## 13. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 性能 | Today 首屏在常规网络下 2.5 秒内可交互；普通搜索 1 秒内返回首批结果 |
| AI 响应 | 提交问题后 2 秒内显示状态或首个流式内容；超时可重试且不重复执行操作 |
| 可用性 | 核心记录、搜索和任务查看在手机端可完整使用 |
| 无障碍 | 键盘可操作；焦点清晰；颜色不是唯一状态表达；目标 WCAG 2.1 AA |
| 可靠性 | 写操作具备幂等保护；同步失败可见、可重试、不静默覆盖本地修改 |
| 可观测性 | 记录接口错误、AI 延迟、检索命中、工具执行失败和同步状态 |

## 14. 数据指标

### 14.1 北极星指标

**每周完成至少一次“记录或检索 → 形成任务/决策 → 标记完成”的有效闭环用户数。**

### 14.2 辅助指标

- 新用户在首次访问 10 分钟内完成第一条记录的比例。
- 每周使用 Today、Knowledge、Assistant 中至少两个模块的用户比例。
- 带有效引用的 AI 回答比例，以及用户打开引用的比例。
- AI 操作草稿的接受、编辑和放弃比例。
- 每周复盘生成率与保存率。
- AI 响应时间、失败率、单个活跃用户成本。

### 14.3 关键埋点

`onboarding_completed`、`capture_created`、`inbox_processed`、`task_completed`、`goal_created`、`knowledge_searched`、`assistant_asked`、`citation_opened`、`action_previewed`、`action_confirmed`、`action_undone`、`weekly_review_saved`。

## 15. MVP 范围与发布标准

### 15.1 MVP 必须包含

- 邮箱登录与演示模式。
- Today、Inbox、任务、目标、基础周日历、笔记和关键词搜索。
- 基于笔记与任务的语义问答和来源引用。
- AI 创建任务草稿、目标拆解草稿、每周复盘草稿。
- 写操作确认、执行日志、数据导出和删除入口。

### 15.2 MVP 暂缓

- 多人协作、移动原生 App、邮件自动处理。
- 多个第三方日历双向同步。
- 自动重排日程和完全自治的 Agent。
- OCR、音频笔记、复杂双向链接图谱。
- 付费订阅与团队工作区。

### 15.3 发布验收场景

一个首次访问的用户应能在 10 分钟内：创建一个目标、记录两条笔记和三个任务；让 AI 基于这些内容回答一个带引用的问题；预览并确认创建一条任务；最后在 Today 中看到新的安排。

## 16. 迭代路线

- **M0：体验原型**——Today、快速记录、AI 对话和目标拆解的可点击原型。
- **M1：基础闭环**——账号、任务、目标、笔记、搜索和演示数据。
- **M2：可信 AI**——语义检索、引用、操作草稿、确认与审计。
- **M3：时间系统**——日历连接、时间块、冲突提醒和周复盘。
- **M4：生态扩展**——更多导入源、移动端优化和可选自动化。

## 17. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 功能过多导致体验像工具拼盘 | 核心价值不清晰 | MVP 围绕“今日聚焦”和“可信 AI 操作”收敛 |
| AI 错误理解日期或意图 | 创建错误任务 | 所有写入先预览；日期用结构化解析和时区校验 |
| 检索回答看似正确但无依据 | 损害信任 | 强制引用、置信提示和无证据拒答 |
| 私人数据泄露 | 严重安全问题 | 数据隔离、最小权限、脱敏日志、删除索引联动 |
| 第三方同步冲突 | 数据被覆盖 | MVP 先只读；保留来源、版本和冲突界面 |
| 模型成本不可控 | Demo 难以持续 | 缓存、上下文裁剪、模型分级和单用户配额 |

## 18. 等待个性化确认的问题

1. 你本人最希望这个系统解决的是学习、求职、开发项目，还是日常生活管理？
2. 首发是否连接真实日历，还是先用产品内部日历完成闭环？
3. 是否要突出“本地优先/隐私优先”，例如支持完全本地存储或本地模型？
4. 主页 Demo 是开放访客体验，还是只展示录屏和测试账号？
5. 视觉风格更偏“操作系统控制台”、极简知识工具，还是未来感 AI 界面？
6. 目标用户只服务个人，还是未来需要支持教练、导师与学生之间的协作？
